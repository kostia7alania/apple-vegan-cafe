# Grab Photo Recovery

Recover the only surviving copies of merchant images into private staging. Keep capture,
reconciliation, recovery, and publication as separate gates.

Read [references/contract.md](references/contract.md) before capturing or downloading data.

## Workflow

### 1. Select the source

Prefer, in order:

1. A copied JSON response body from the authenticated GrabMerchant catalogue.
2. An official GrabFood Partner API menu payload supplied by an approved partner.
3. A sanitized HAR exported without sensitive data.

Do not scrape the consumer GrabFood site. Do not ask for, inspect, or store cookies, passwords,
OTP values, authorization headers, browser profiles, or request bodies.

### 2. Capture through the merchant's browser when needed

Use the installed browser-control skill and the merchant's existing browser session. Open
`https://merchant.grab.com/portal`. If authentication is required, leave the login tab open and
ask the user to sign in and tell Codex when it is ready. Never enter or inspect credentials.

After login:

1. Open Catalogue/Menu in the visible UI.
2. Enable CDP Network observation before loading the catalogue.
3. Capture successful GET JSON responses only.
4. Use `Network.getResponseBody` for candidate responses.
5. Keep only a response body containing a `categories[].items[].photos[]` subtree.
6. Save only that JSON body to a temporary file. Never save request headers or replay requests.

### 3. Discover mappings and exact hosts

Run from the Apple Vegan Cafe repository:

```bash
pnpm grab:photos -- --input /private/tmp/grab-menu-response.json --provenance ai-generated
```

Discovery is read-only. Confirm that:

- `mappedItems` matches the current ItemID map (144 as of 2026-08-14);
- captured IDs resolve through `scripts/data/grab-item-map.json`;
- `unmappedItemIdsCount` is zero or explicitly explained;
- `photoCandidates` is plausible;
- every printed host is an exact expected image host.
- each `candidates[]` row has the expected ItemID/dish target plus query-redacted origin and URL
  hashes.

Never approve a wildcard or a guessed Grab CDN host.

### 4. Recover bytes into private staging

Create a temporary parent, then use a new child path so the connector can publish the batch
atomically:

```bash
recovery_parent=$(mktemp -d /private/tmp/apple-grab-recovery.XXXXXX)
pnpm grab:photos -- \
  --input /private/tmp/grab-menu-response.json \
  --provenance ai-generated \
  --allow-host exact-host-from-discovery.example \
  --output "$recovery_parent/batch" \
  --write
```

Repeat `--allow-host` for each exact discovered host. The connector validates DNS, redirects,
Content-Type, magic bytes, size, decoded dimensions, SHA-256, duplicate ItemIDs, and exact map
targets. It strips URL query strings from the saved manifest.

Do not use `--provenance owner-original` for pixels generated by ChatGPT. Use `ai-generated`.

### 5. Review the batch

Inspect `manifest.json` and a representative sample of recovered files. Verify exact dish identity
with the owner. Quarantine missing, ambiguous, or visually mismatched assets; never fall back to
names or image similarity.

The recovery batch is not deployable content. Keep it outside the repository and `public/`.

### 6. Publish only through a separate explicit task

AI-generated food images are illustrations, not documentary photos of served dishes. Do not add
them to a dish merely because recovery succeeded. The dish media schema can represent
`ai-generated` illustrations, but publication still requires all of the following:

- the owner confirms that the recovered image belongs to that exact Grab ItemID and may be
  published on this website;
- the asset keeps `origin: ai-generated` and complete rights, confirmation, and people-review
  metadata;
- the UI renders the localized visible illustration disclosure; and
- the publication patch changes only the approved dish `images` array plus its derivatives, with
  no editorial or ItemID-map drift.

Recovery alone must not change dish JSON or ItemID mappings.

## Failure rules

- No authenticated merchant session: stop at the login handoff; continue local connector work.
- No menu JSON subtree: ask for a copied catalogue Fetch/XHR response, not credentials.
- Sensitive HAR fields: reject the file and request `Export HAR (sanitized)`.
- Signed or unknown host: discover it, but do not download until that exact host is allowed.
- More than one photo for an ItemID or different URLs for the same ItemID: fail closed.
- Download requiring cookies: stop and report the unsupported authenticated-asset case; never
  export cookies or claim the batch is recovered.
- AI-generated provenance: preserve the bytes and mapping, but mark the batch illustration-only.

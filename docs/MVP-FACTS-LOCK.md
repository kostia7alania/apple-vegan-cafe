`line_url_full_https` ต้องเป็นลิงก์เต็ม ไม่ใช่ LINE ID; `whatsapp_url_full_https`
ต้องเป็นลิงก์เต็มเช่นกัน Google Business Profile URL และ direct review URL
เป็นคนละลิงก์ กรุณาอย่าใส่ลิงก์เดียวกันโดยไม่ตรวจสอบ

`maps_share_url` ต้องมาจากเจ้าของร้านที่เปิดโปรไฟล์/หมุดจริงใน Google Maps
กด Share แล้ววางลิงก์เท่านั้น ห้ามคัดลอกลิงก์หรือพิกัดจากเว็บไดเรกทอรี
เพราะอาจปักหมุดผิดที่ หลังได้ลิงก์จากเจ้าของแล้วผู้พัฒนาจึงตรวจ Place ID และพิกัด
ก่อนย้ายเข้า production ให้นักพัฒนาตรวจ Place ID/CID ชื่อ เบอร์โท ที่อยู่ และตำแหน่งหมุดจากลิงก์ที่เจ้าของส่งเท่านั้น

`grabfood_share_url_full_https` และ `line_man_share_url_full_https` ต้องเป็นลิงก์สั่งอาหาร
หรือ share link ทางการของร้าน ไม่ใช่ลิงก์ค้นหาหรือหน้าร้านอื่น ถ้าแพลตฟอร์มยังไม่ยืนยันว่า
เปิดรับออเดอร์อยู่ ให้ตอบ `unknown` และอย่าเพิ่มลิงก์นั้นในเว็บไซต์ค่ะ ระบบรองรับเฉพาะ
GrabFood และ LINE MAN และจะไม่แสดงแพลตฟอร์มที่ไม่มีลิงก์จริง

## Intake checker — ตรวจคำตอบก่อนย้ายเข้า CMS

ถ้ายังไม่สะดวกตอบแบบฟอร์มฉบับเต็ม ให้ผู้พัฒนารัน `pnpm intake:round1` แล้วส่งผลลัพธ์
ให้เจ้าของตอบรอบแรกได้ค่ะ แบบสั้นมี 25 บรรทัดคำตอบสำหรับแผนที่/ที่อยู่, เวลาปกติ,
ช่องทางข้อความ, การชำระเงิน, pickup/ราคา, delivery, สถานะ reservation และ final permission
ส่วนรายละเอียด reservation, food facts, media และ privacy อยู่ใน Round 2 ด้านบน

ข้อความ candidate หลัง `#` มาจากไฟล์ปัจจุบัน อาจเก่าหรือขัดแย้งและไม่ใช่ข้อมูลที่เจ้าของ
ยืนยัน จึงต้องยืนยัน/แก้ไข/ตอบ `unknown` ทุกกลุ่ม คำตอบจริงเริ่มเป็น `unknown` หรือ checkbox
ว่างเสมอ และ final permission ครอบคลุมเฉพาะค่า Round 1 ที่เจ้าของยืนยันในข้อความนั้น
ไม่ครอบคลุม Round 2 คำสั่งนี้พิมพ์ stdout อย่างเดียว ไม่แก้ content/CMS/files
หลังได้รับคำตอบจึงบันทึกเป็น `.md`/`.txt` และตรวจด้วย `pnpm intake:check -- <file>` ตามเดิม

บันทึกคำตอบที่กรอกแล้วเป็นไฟล์ `.md` หรือ `.txt` จากนั้นให้ผู้พัฒนารัน:

```sh
pnpm intake:check -- /path/to/filled-facts-lock.md
```

สคริปต์นี้อ่านอย่างเดียวและ **ไม่แก้ CMS หรือไฟล์ content** ค่ะ ผลลัพธ์เรียงคงที่เป็น
`ERRORS`, `CONFIRMED`, `BLOCKED` และ `PUBLISHABLE MAPPINGS` ค่า `unknown`, ช่องว่าง
และ `____` จะอยู่ใน BLOCKED เสมอ; mappings จะไม่แสดงจนกว่าจะติ๊ก
`permission_to_publish_confirmed_information` และกรอก final confirmer/date/contact ครบ

| Intake fields                                        | Manual target after review                                   |
| ---------------------------------------------------- | ------------------------------------------------------------ |
| owner-shared maps URL; developer-verified coordinate | `locations.json:pattaya.mapsUrl / geo`                       |
| LINE/WhatsApp/preferred channel/response hours       | `settings.json:site.*`                                       |
| payment methods, price, pickup, reservations         | `operations.json:pattaya.*`                                  |
| spice requests, dietary contact, halal guidance      | `operations.json:pattaya.*`                                  |
| repeated verified priority-dish facts                | `dishes/<exact-slug>.json:foodFacts.*`                       |
| landmark/parking/arrival note                        | `locations.json:pattaya.*`                                   |
| confirmed GrabFood/LINE MAN links                    | `settings.json:site.orderingLinks`                           |
| Google profile/direct-review URLs                    | `settings.json:site.reviewLinks.*`                           |
| per-file granted media permission/consent/alt/credit | `site-media.json:site.assets[kind]` หลังเตรียมไฟล์และขนาดภาพ |

ตอนนี้ checker แปลงเวลาปกติหนึ่งช่วง, ที่อยู่แก้ไข, payment note, pickup note และ
priority-dish facts ที่ยืนยันแล้วได้ แต่ยังไม่แปลง last kitchen order,
กระบวนการวันหยุด หรือ delivery-area/notes สคริปต์จะแสดงรายการเหล่านี้ใน
`UNSUPPORTED / MANUAL` เพื่อไม่ให้ใครเข้าใจผิดว่า import ได้อัตโนมัติค่ะ

รูปแบบเวลาที่ checker รับคือวันภาษาอังกฤษคั่นด้วย comma และเวลา 24 ชั่วโมงค่ะ
ถ้าทุกวันเวลาเดียวกัน ใช้ `dine_in_hours: 07:00-22:00`; ถ้าแต่ละวันต่างกัน ใช้
`dine_in_hours: mon,tue=07:00-22:00;wed,thu=08:00-21:00` โดยทุก open day
ต้องอยู่ในหนึ่งช่วงพอดี ตัวอย่างร้านเปิดทุกวันคือ
`open_days: mon,tue,wed,thu,fri,sat,sun` และ `regular_closed_days: none`
ถ้ามีรูปแบบอื่นที่ format นี้อธิบายไม่ได้ ให้ตอบ `unknown` และส่งตารางแยก ห้ามเดาค่ะ

## Price + reservation gate — ห้ามสรุปแทนเจ้าของ

- `price_policy: unknown` จะแสดงข้อความกลาง ๆ เท่านั้น เลือกค่าอื่นเมื่อเจ้าของ
  ยืนยันความสัมพันธ์ระหว่างราคาหน้าร้าน รับเอง เว็บไซต์ และ GrabFood แล้ว
- `reservations: unknown` จะไม่แสดงส่วนจองโต๊ะ; `not-accepted` แสดงว่าไม่รับจอง
  โดยไม่สร้างปุ่มติดต่อ
- `accepted` ต้องมี `reservation_channel` ที่ใช้งานจริงและ lead time ครบ EN/TH/RU;
  `large-groups-only` ต้องมี minimum party size เพิ่มด้วย
- ปุ่มบนเว็บไซต์เป็นเพียงคำขอ/สอบถามการจอง ไม่ใช่การยืนยันโต๊ะอัตโนมัติ

## Spice-request gate — ระดับปกติไม่ใช่คำสัญญาว่าปรับได้

- `spice_requests: unknown` ไม่แสดงข้อความเรื่องการปรับระดับความเผ็ด
- `offered` ต้องมี request level อย่างน้อย 1 ค่า, ขอบเขต/ข้อจำกัดครบ EN/TH/RU,
  ผู้ยืนยัน และวันที่ยืนยัน
- `not-offered` ต้องเว้น levels และ scope ว่าง แต่ยังต้องมีผู้ยืนยันและวันที่
- `spicyLevel` ในข้อมูลแต่ละเมนูหมายถึงความเผ็ดของสูตรปกติเท่านั้น ห้ามใช้เป็น
  หลักฐานว่าครัวปรับความเผ็ดตามคำขอได้

## Food-facts gate — ตรวจทีละเมนู ห้ามเดา

- คัดลอก block ตั้งแต่หัวข้อ `PRIORITY DISH FACTS` ถึง `verifiedAt_yyyy_mm_dd`
  หนึ่งครั้งต่อหนึ่งเมนู แต่ละ block แยกจากกัน ห้ามรวมหลายเมนูในค่าเดียว
- แม้ชื่อ field จะเป็น `dish_name_or_slug` ต้องใส่ **slug/file stem ที่มีอยู่จริงเท่านั้น**
  เช่น `vegan-pad-thai` จาก `src/content/dishes/vegan-pad-thai.json` ห้ามใส่ชื่อเมนู
  path หรือ `.json`
- `spicyLevel: unknown` หมายถึงยังไม่ตรวจ; `0` หมายถึงครอบครัวยืนยันแล้วว่า
  สูตรพื้นฐานไม่เผ็ด และ `1–3` คือระดับพื้นฐานที่ยืนยันแล้ว
- Allergens ใช้ `unknown` จนกว่าจะตรวจสูตร/วัตถุดิบจริง เมื่อใช้ `verified`
  ต้องตอบ `allergens_contains: none` อย่างชัดเจน หรือใส่เฉพาะ ID ที่รองรับ
  `peanut,soy,gluten`; ช่องว่างไม่แปลว่า allergen-free และไม่รับรองว่าไม่มี
  cross-contact
- `noGlutenIngredients` และ `jainFriendly` เป็น `unknown | yes | no` แยกกัน
  ค่า `yes` ของ Jain ยืนยันเฉพาะสูตรมาตรฐาน ไม่ใช่คำสัญญาว่าปรับแต่งได้ทุกแบบ
- เมื่อมีข้อมูลที่ไม่ใช่ `unknown` อย่างน้อยหนึ่งค่า ต้องกรอก `verifiedBy`
  และ `verifiedAt_yyyy_mm_dd`; ถ้าสูตรหรือ supplier เปลี่ยน ให้ล้าง/ตรวจใหม่
- ค่า `unknown` จะไม่สร้าง mapping และ checker แสดงเพียง
  `field -> src/content/dishes/<slug>.json:foodFacts.*` เพื่อให้ผู้พัฒนาตรวจเอง
  สคริปต์ไม่แก้ไฟล์เมนู
- ห้ามยืนยันหลายเมนูพร้อมกันจากชื่อ หมวดหมู่ รูปถ่าย หรือค่าตั้งต้นในระบบ
- `dietary_questions_contact` เลือกได้เมื่อทีมตอบคำถามเรื่องส่วนผสมผ่านช่องทางนั้นจริง;
  คำตอบเรื่องส่วนผสมไม่ใช่การรับรองว่า allergen-free และไม่สัญญาว่าปรับสูตรได้

## Media gate — ห้ามอัปโหลดก่อนยืนยันสิทธิ์

- เมื่อ `permission` เป็น `pending`, `unknown` หรือ `denied` ห้ามอัปโหลดไฟล์เข้า
  CMS, `public/uploads` หรือเพิ่มไฟล์ใน public site-media registry
- เพิ่มไฟล์ใน public registry ได้เฉพาะเมื่อ `permission: granted`,
  `permission_scope: website_and_derivatives` และกรอก `rights_holder`,
  `confirmed_by`, `confirmed_at_yyyy_mm_dd` ครบแล้ว
- ค่า owner intake `identifiable_people` แปลงเป็น public registry ดังนี้เท่านั้น:
  `no` ใช้ได้หลังตรวจภาพอย่างชัดเจนแล้ว และแปลงเป็น
  `peopleVisibility: none-confirmed`; `yes` แปลงเป็น
  `peopleVisibility: recognisable-present` และต้องมี `people_consent: granted`
- ถ้า `identifiable_people: unknown` ห้ามอัปโหลดหรือเพิ่มใน registry; ค่า
  `people_consent` อื่นที่ไม่ใช่ `granted` สำหรับ `recognisable-present`
  ต้อง fail closed และห้ามเผยแพร่
- สิทธิ์จาก checkbox ยืนยันข้อมูลทั่วไปด้านบนไม่แทนที่ permission รายไฟล์
